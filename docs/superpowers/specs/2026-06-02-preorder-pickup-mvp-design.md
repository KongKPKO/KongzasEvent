# Pre-order and Pickup MVP Design

## Goal

Add a first version of pre-ordering before an event and pickup management during the event, while preserving Nireq's current queue, menu, POS, and event stock model.

The feature should make Nireq feel like an event commerce workflow:

- Before event: customers can reserve items without joining a queue.
- During event: staff can find and mark pre-orders as picked up.
- After this MVP: the same structure can support post-event sales.

## Product Positioning

BoothMate is strongest as a seller-side POS for artist alley tables. Nireq should not clone that product directly. Nireq's stronger wedge is customer-facing event commerce around the booth:

- customers can discover the creator,
- browse an event catalog,
- order before reaching the booth,
- join/manage queue when the booth is live,
- and give creators a clear fulfillment list.

Pre-order and pickup is the best next feature because it extends existing event catalog, stock reservation, customer menu, POS, and dashboard concepts without needing a payment provider or shipping engine in the first pass.

## MVP Scope

### Included

- Event-level pre-order settings.
- Customer pre-order checkout from the existing menu experience.
- Pre-order orders that reserve stock and do not require a queue ticket.
- Customer identity fields: name, contact, and note.
- Pickup code generated by the backend.
- Staff pickup list for one event.
- Staff action to mark a pre-order as picked up.
- Staff/manager action to cancel a pre-order and release reserved stock.
- End-of-event expiry path for no-show pre-orders so stock is not locked forever.
- Basic dashboard/history visibility for pre-order order type and pickup state.

### Deferred

- Online payment automation.
- Shipping labels and carrier integrations.
- Customer accounts.
- Full offline order sync.
- Split settlement by booth member.
- Post-event store mode.
- Product variants.

## Data Model

### Events

Add event fields:

- `selling_mode`: `preorder`, `live`, `post_event`, or `closed`.
- `preorder_opens_at`: optional timestamp.
- `preorder_closes_at`: optional timestamp.
- `preorder_pickup_instructions`: optional text shown to customers after ordering.

The first pass keeps `events.status` and `events.is_booth_open` behavior unchanged:

- `status` still controls whether the event is real/confirmed.
- `is_booth_open` still controls live queue behavior.
- `selling_mode` controls what commerce action the customer sees.

### Orders

Add order fields:

- `order_type`: `live_queue`, `pos_walkin`, `preorder`, or `post_event`.
- `pickup_code`: short public code generated by the backend.
- `customer_name`: required for pre-order.
- `customer_contact`: optional but recommended.
- `customer_note`: optional.
- `pickup_status`: `not_required`, `awaiting_pickup`, `picked_up`, `cancelled`, or `expired`.
- `picked_up_at`: timestamp.
- `picked_up_by`: auth user id of the staff member who marked pickup.
- `cancelled_at`: timestamp.
- `cancelled_by`: auth user id of the staff member who cancelled the pre-order.
- `cancel_reason`: optional text.

Existing live queue orders should default to `live_queue`. Existing walk-in orders should be set by the walk-in RPC to `pos_walkin`. Existing rows can default to `live_queue` because current customer orders are queue-based unless `queue_id` is null. A backfill should set null-queue completed orders to `pos_walkin`.

### Stock

Pre-orders should use the existing stock invariant:

```text
available = stock_total - stock_reserved - stock_sold
```

Pre-order creation increments `stock_reserved` for finite stock, just like current queue customer orders. Pickup completion converts reserved stock into sold stock by using a dedicated pickup RPC, not by directly updating rows from the frontend.

Pre-orders must also have a release path. Cancelling or expiring a pre-order decrements `stock_reserved` for finite stock and marks the order as non-fulfillable. Without this, no-show customers would permanently lock stock and make finite products appear sold out even when the physical item remains at the booth.

Event catalog rows remain the preferred stock source when an event has `event_products`; product-level stock remains the fallback when an event has no event catalog rows.

## Customer Flow

1. Customer opens `/:slug/menu`.
2. If selected event is in pre-order mode and the pre-order window is open, the menu shows pre-order copy and does not require a queue ticket.
3. Customer adds items to cart.
4. Customer enters name, contact, and optional note.
5. Customer submits the pre-order.
6. Backend reserves stock and returns `order_id`, `pickup_code`, and pickup instructions.
7. Customer sees a receipt state and can reopen it from local storage.

If the event is live and the booth is open, existing queue behavior remains available. The first pass does not allow a single customer cart to mix pre-order and live queue checkout modes.

## Creator Flow

1. Creator opens event management.
2. Creator opens pre-order settings for an event.
3. Creator sets `selling_mode = preorder`, pre-order open/close timestamps, and pickup instructions.
4. Creator uses the existing event catalog workspace to choose products and stock.
5. Creator shares the same public artist/event link.

The first pass can add the pre-order settings entry point from the event card rather than creating a large event hub redesign.

## Staff Pickup Flow

1. Staff opens a new pickup page for an event.
2. Staff searches by pickup code, customer name, customer contact, or product name.
3. Staff filters by `awaiting_pickup`, `picked_up`, or all.
4. Staff marks an order as picked up.
5. Backend verifies staff role, converts reserved stock to sold stock, marks the order `completed`, and records pickup timestamp/staff.
6. If the customer cancels or never arrives, owner/manager/seller can cancel the order and release reserved stock.

Queue staff should be allowed to mark pickups because pickup is an operational booth task. Only owner, manager, and seller should be allowed to cancel/expire pre-orders because those actions release sellable stock and may affect future payment/refund rules.

## Backend RPCs

### `create_preorder_with_stock`

Inputs:

- `p_event_id uuid`
- `p_items jsonb`
- `p_customer_name text`
- `p_customer_contact text`
- `p_customer_note text`
- `p_client_request_id uuid default null`

Returns:

- `order_id uuid`
- `pickup_code text`
- `total_price numeric`
- `currency text`
- `pickup_instructions text`

Rules:

- Event must be confirmed.
- Event `selling_mode` must be `preorder`.
- Current time must be between `preorder_opens_at` and `preorder_closes_at` when those fields are set.
- Event must not be ended.
- Product must be enabled and visible in the event catalog when the event catalog exists.
- Finite stock must have enough availability.
- Mixed currency is rejected.
- Customer name is required.
- `p_client_request_id` provides idempotency for retry-safe customer submissions.
- The RPC should check that the artist is public and verified, matching the public customer surface. Owner/staff preview can use authenticated management pages instead of public pre-order creation.
- The stock concurrency strategy intentionally locks the product row (`for update of p`) even when event stock is used. This serializes orders for the same product and prevents oversell across concurrent pre-order submissions.

### `mark_preorder_picked_up`

Inputs:

- `p_order_id uuid`

Returns:

- `order_id uuid`
- `pickup_status text`
- `status text`
- `picked_up_at timestamptz`

Rules:

- Caller must have event role `owner`, `manager`, `seller`, or `queue_staff`.
- Order must be `order_type = preorder`.
- Order must be `status = confirmed`.
- Order must be `pickup_status = awaiting_pickup`.
- Reserved stock moves to sold stock.
- Order becomes `completed`.
- Pickup status becomes `picked_up`.

### `cancel_preorder_with_stock`

Inputs:

- `p_order_id uuid`
- `p_reason text default ''`

Returns:

- `order_id uuid`
- `pickup_status text`
- `status text`
- `cancelled_at timestamptz`

Rules:

- Caller must have event role `owner`, `manager`, or `seller`.
- Order must be `order_type = preorder`.
- Order must be `status = confirmed`.
- Order must be `pickup_status = awaiting_pickup`.
- Reserved stock moves back to available stock.
- Order becomes `cancelled`.
- Pickup status becomes `cancelled`.
- Reason is stored when provided.

### `expire_preorders_for_event`

Inputs:

- `p_event_id uuid`

Returns:

- `expired_count integer`

Rules:

- Caller must have event role `owner` or `manager`.
- Event must be ended or manually closed.
- Every awaiting pre-order for the event releases reserved stock.
- Each affected order becomes `cancelled` with `pickup_status = expired`.
- This can be run from the pickup page after event end. A future scheduled job can call the same RPC.

### `get_public_order_receipt`

Inputs:

- `p_order_id uuid`
- `p_pickup_code text`

Returns:

- `status text`
- `pickup_status text`
- `pickup_code text`
- `customer_name text`
- `total_price numeric`
- `currency text`
- `pickup_instructions text`

Rules:

- Public callers can only read the narrow receipt when both `order_id` and `pickup_code` match.
- The response does not expose staff notes, internal IDs beyond `order_id`, or other customer orders.

## UI Surfaces

### Customer Menu

`MenuView` should branch checkout behavior by event mode:

- `live` or default: existing queue-required submit flow.
- `preorder`: pre-order checkout form and receipt state.
- `closed`: browsing only, no submit.
- `post_event`: deferred for later but reserved in the event mode type.

### Creator Event Management

`ManageArtist` should expose a pre-order settings action for confirmed/upcoming events. The settings modal or page should edit the event mode fields and show a short readiness checklist:

- event catalog has at least one enabled product,
- finite stock is allocated when products are not unlimited,
- pre-order close time is before event end,
- pickup instructions are present.

The settings page must display event-local times correctly. It should use the event timezone helpers already in the repo instead of `toISOString().slice(0, 16)`, because `datetime-local` inputs display local wall-clock time and ISO UTC slicing shifts Bangkok times by seven hours.

### Staff Pickup

Create `PreorderPickup.tsx` as a focused event operations page. It should not be embedded into `PosPanel` in the first pass because pickup is a different workflow from charging live carts.

## Testing

### Database Tests

Cover:

- pre-order creation succeeds during an open pre-order window,
- pre-order creation fails when mode is not `preorder`,
- pre-order creation fails outside the window,
- finite stock reservation prevents oversell,
- pickup converts reserved stock to sold stock,
- pickup cannot be repeated,
- cancel releases reserved stock,
- expiring event no-shows releases reserved stock,
- public receipt only works with matching order id and pickup code,
- anonymous users cannot select customer-identifying fields directly from `orders`,
- walk-in RPC writes `order_type = pos_walkin`,
- unauthorized pickup fails.

### Frontend Tests

Cover:

- customer pre-order checkout does not require a queue ticket,
- customer queue checkout still requires a queue ticket in live mode,
- pickup list displays awaiting pickup orders,
- pickup action changes the order row state.

## Acceptance Criteria

- A creator can enable pre-order mode for one event.
- A customer can submit a pre-order without joining a queue.
- Stock is reserved immediately and cannot oversell.
- Customer receives a pickup code.
- Staff can search and mark the pre-order as picked up.
- Owner/manager/seller can cancel no-show pre-orders and release stock.
- Owner/manager can expire all remaining event pre-orders after the event ends.
- Picked-up pre-orders appear as completed orders in history/dashboard.
- New walk-in POS orders are labeled `pos_walkin`.
- Public receipt access is only available through the narrow receipt RPC.
- Existing live queue ordering and walk-in POS still work.
